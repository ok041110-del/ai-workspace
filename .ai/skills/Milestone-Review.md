# Skill: Milestone Review (마일스톤 검토)

## 1. 목적
이 Skill의 목적은 하나의 이정표(Milestone)가 최종 완성 단계에 도달했을 때, Milestone 하위의 모든 작업들이 목표한 품질 가이드라인과 설계 제약을 만족하며 100% 완결되었는지 종합 검증하는 것입니다. 기술 부채의 잔재를 투명하게 식별하고, 전체 테스트 패키지의 내구성을 확보하며, 다음 Milestone으로의 안전한 진입 준비를 끝마쳤음을 정량적 사실을 통해 엄격하게 증명합니다.

## 2. 사용 시점
- 특정 Milestone 내에 기획된 모든 세부 Task들의 상태가 `DONE`으로 전이되었을 때
- 다음 Milestone을 기획하거나 사용자에게 최종적인 Milestone 완료 승인 요청을 수행하기 전
- 지금까지 누적된 구조적 결함과 미해결 이슈를 정리하고 기술적 빚(Technical Debt)을 파악하고자 할 때

## 3. 입력
종합적인 거버넌스 검토를 위해 다음 자원 전체를 Source of Truth로 상정하고 연동 대조합니다:
- **전체 로드맵 및 백로그**: `docs/ROADMAP.md`, `.ai/TASKS.md`
- **프로젝트 장기 메모리**: `.ai/MEMORY.md`
- **구현 영역의 전체 테스트 스위트 결과**: `tests/` 이하의 모든 테스트 파일 실행 상태
- **전체 프로덕션 소스코드 및 인터페이스**: `src/` 이하의 전체 파일 상태
- **적용 규정**: `.ai/RULES.md`

## 4. 출력
사용자가 프로젝트의 전반적인 건강도와 다음 실행 가능성을 정량적으로 판정할 수 있도록 유도하는 **Milestone 완료 검토 보고서**를 출력합니다:
- **Milestone 목표 달성률 정량 보고**: 완료된 Task 수 / 계획된 Task 수 (100% 달성이 기본)
- **종합 품질 지표**: 전체 단위/통합 테스트 개수, 테스트 커버리지, 코드 라인 수 정보
- **정적 분석 및 린트 상태 요약**: Ruff, MyPy 등의 실행 이력 요약
- **식별된 잔존 기술 부채 목록**: 당초 설계와 어쩔 수 없이 타협한 부분 및 다음 마일스톤에서 반드시 해소해야 할 마이너 리팩토링 요소
- **문서 동기화 보증**: 기결정된 ADR 들의 최신 갱신 상태 보증
- **다음 Milestone 준비도 진단**: 다음 Milestone 이정표를 즉각 착수하기 위해 정의되어야 할 백로그 상태 진단

## 5. 작업 절차

### 5.1 완료 정의 부합성 정량 검토
1. 대상 Milestone에 정의된 'Definition of Done(DoD)'의 모든 세부 제약을 하나씩 불러옵니다.
2. `.ai/TASKS.md` 상에서 해당 Milestone 소속의 모든 Task ID가 정확히 `DONE`으로 전이되어 있고, 진행 로그 상에 빈틈없이 이력이 남겨졌는지 체크리스트 형식으로 대조합니다.

### 5.2 전체 테스트 내구성 및 회귀 검증 (Test Before Complete)
1. 저장소 전체를 대상으로 모든 테스트 스위트를 구동합니다 (예: `poetry run pytest`).
2. 특정 환경이나 타이밍에 종속되어 불규칙하게 실패하는 테스트(Flaky Test)가 존재하는지 관찰하고 완벽하게 해소합니다.
3. 코드 변경으로 인한 기존 영역의 기능 퇴화(Regression)가 전혀 없음을 정량적으로 확실히 파악합니다.

### 5.3 소스 코드 정적 품질 완전성 보증
1. 전체 모듈을 정적 정밀 분석 도구로 분석합니다:
   - `poetry run ruff check .`
   - `poetry run mypy .`
2. 분석 도구가 단 하나의 경고(Warning)나 타입 오류(Type Error)라도 리포트하는 경우, 이를 완전히 해소하기 전에는 Milestone Review 단계를 통과시키지 않습니다.

### 5.4 기술 부채 투명화 및 기록
1. 구현 일정상의 긴급성으로 인해 부득이하게 임시 코드 구조로 타협한 영역을 추적합니다.
2. 발견된 구조적 아쉬움이나 잠재적 한계를 "기술 부채(Technical Debt)"라는 명목으로 숨김없이 드러내고, 다음 Milestone 착수 시점에 가장 먼저 소거할 수 있도록 보고서 및 `.ai/MEMORY.md`에 확실히 기록합니다.

### 5.5 후속 계획 수립 및 준비 상태 체크
1. `docs/ROADMAP.md`를 기반으로, 다음 Milestone의 예정 작업 영역을 세부 Task 단위로 안전하게 분해하기 위한 기초 기획을 검토합니다 (Task Driven Development).
2. 사용자에게 Milestone 완료 보고를 올리고, Approval Required 규칙에 따라 최종 확인과 다음 단계 승인 절차를 전개할 수 있도록 논리적으로 정돈합니다.

## 6. 수행 원칙
- **Approval Required**: Milestone 완료는 사용자의 최종적인 검토와 직접적인 서면 승인이 요구되는 엄격한 게이트웨이입니다. 승인 없이 독단적으로 다음 Milestone으로 월반하여 구현하는 것을 철저히 차단합니다.
- **Repository First**: 단순한 체크리스트 수기 체크에 의존하지 않고, 항상 실제 소스코드 저장소의 빌드, 린트, 테스트 구동 사실에 의거하여 완료 상태를 입증합니다.
- **Strict SRP & SOLID Compliance**: 한 번 무너진 설계는 복구하는 데 수배의 비용이 소요됩니다. Milestone 단계가 종료되는 시점에는 어질러진 의존성 방향과 어색한 결합도를 완벽하게 가다듬어 단단한 기반을 지속시킵니다.

## 7. 금지 사항
- **미완료 Task 방치 금지**: 단 하나의 Task라도 `TODO`나 `IN_PROGRESS` 혹은 `BLOCKED` 상태로 잔재해 있는 경우, 절대 Milestone 이 완료되었다고 허위 보고하거나 타협하여 게이트를 통과시키지 않습니다.
- **정적 분석 위반 잔존 금지**: Ruff나 MyPy 상의 경고나 무시 구문(`noqa`, `type: ignore`)을 무분별하게 남발하여 분석 결과를 우회해 두고 완료를 선언하는 편법을 완전히 금지합니다.

## 8. 완료 조건
- Milestone 소속 모든 Task 가 100% 성공적으로 이행되어 `DONE`으로 전이되었을 때
- 전체 테스트 패키지 및 Ruff, MyPy가 무결점 통과(0 Error, 0 Warning)를 증명했을 때
- 기술 부채와 다음 Milestone 준비 컨텍스트가 `.ai/MEMORY.md` 및 로드맵에 완전하게 가시화되었을 때
